# 2026-10-05: use and migration notes

## Release scope and verification

This candidate combines the independent **Corrective action aging** report,
the QSL export post-query identity-revocation fix, four isolated fault-drill
groups, the offline `change_impact.py` CLI, and the native 50-scenario browser
publication gate. It keeps the existing `app.py`, routes, product dependency
pins and synthetic-only integration boundary.

The owner authorized uploading a dedicated validation branch, requiring full
Python 3.8/3.10 regression plus all 50 browser scenarios, then a normal
fast-forward main update and exact-SHA CI verification. Main must not advance
on partial, failed, stale or unrun browser evidence. The
[workflow](../../.github/workflows/reporting-tests.yml) and
[gate contract](../quality-actions/CI_PUBLICATION_GATE.md) define the checks.
Read the GitHub Actions result for the exact revision being used; this document
is not by itself evidence that a remote run has passed.

Six Windows-specific tests are skipped on Linux. Linux results do not certify
Windows, the exact company Linux kernel/Python patch versions, real
Oracle/LDAP/SMTP/Flask-RESTX/SQLALCHEMY_BINDS integrations or deployment.
The 15% time / 10% RSS acceptance policy remains unapproved and disabled.

## Update an existing checkout safely

1. Stop the local app and its owned workers before changing its code or state.
   Keep any local changes; inspect `git status --short` and do not reset them.
2. If using persisted state, retain the complete stopped SQLite set and the
   current code/environment. Follow the reviewed
   [backup and rollback instructions](../deployment/OPERATIONS.md); copying
   only `workspace.sqlite` omits sibling stores.
3. In a clean checkout on `main`, use `git pull --ff-only origin main` and
   record `git rev-parse HEAD`. If fast-forward fails or local changes exist,
   reconcile them separately instead of forcing or overwriting.
4. Use the existing approved Python environment. This release introduces no
   product dependency or database-schema migration. Do not install the
   historical `requirements.txt` into the company environment as an upgrade.
5. Run `python -B -m unittest discover -s tests -v` and review failures/skips
   before local use. Repository CI does not replace target-environment checks.

## Start the synthetic demo

The normal command remains `python -B app.py`, then open
`http://127.0.0.1:8050/login`. Public synthetic users are `demo-admin`,
`demo-user-a`, and `demo-user-b`; their demo password is `demo-only`.
Do not expose these accounts as production authentication.

Both optional reports are disabled by default. To inspect both in a Linux
shell, from the repository root:

```sh
REPORTING_ENABLE_REPORT_TEMPLATE=1 REPORTING_ENABLE_QUALITY_ACTIONS=1 python -B app.py
```

PowerShell:

```powershell
$env:REPORTING_ENABLE_REPORT_TEMPLATE = '1'
$env:REPORTING_ENABLE_QUALITY_ACTIONS = '1'
python -B app.py
```

The catalog links to `/QA_portal/report-template` and
`/QA_portal/quality-actions`. The new report is read-only, tenant-scoped and
synthetic; its default as-of date is **2026-10-05**, not the current date.
Choose the intended as-of date explicitly. Production rejects these demo flags.
See [report semantics and CSV behavior](../quality-actions/README.md).

## Agent workflow and operational cautions

```sh
python -B tools/change_impact.py --changed reporting_workspace/quality_actions/service.py
python -B tools/change_impact.py --base HEAD~1 --format json
```

The CLI reads local source/Git only. Its output is an evidence-backed planning
hint, not execution or acceptance; never execute commands supplied by an
untrusted report. Full regression remains mandatory before publication.
See [the CLI contract](../change-impact/README.md).

The QSL export fix now rejects an identity that loses authorization during the
query; a denied export must not be worked around by weakening permissions.
Optional reports add no persistent state. Fault drills use isolated synthetic
stores; never point them at live company databases. Existing unknown/uncertain
job outcomes stay pending reconciliation and must not be automatically replayed.
The accepted GitHub workflow uploads only synthetic summaries, hashes and
screenshots, excluding raw logs, credentials, downloaded exports and state.
